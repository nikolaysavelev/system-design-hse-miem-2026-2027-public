# Акт 2. Трейсинг: где время у pay

Ветка `demo/l4-otel`, 26.09.2026, чистая БД, `make checkout-storm` (тот же сценарий, что в акте 1), sampling 1.0.

## Водопад одного pay

`trace-waterfall.png` (Grafana Explore → Tempo) и `trace-waterfall.txt` (текстом), трейс целиком в `trace.json`.
Трейс выбран запросом `make traces-slow Q='{ name = "mailgw.POST /send" && span.retry.attempt = 1 }'`: pay с повтором к шлюзу.

| Этап | Время | Что это |
|---|---|---|
| `pgx.acquire` в начале | 87 мс | очередь на соединение пула под фоновым штормом |
| `sql.begin` | 73 мс | та же очередь, уже в PgBouncer |
| `payment.Charge` → `psp.emulate` | 317 → 300 мс | PSP (in-process эмулятор) |
| `ticketing.Issue` → `notification.Send` | 2 180 мс | почта внутри запроса |
| `mailgw.POST /send` retry.attempt=0 | 1 034 мс, **502** | серверный span `mailgw: POST /send` рядом: время на стороне шлюза |
| `mailgw.POST /send` retry.attempt=1 | 1 140 мс, 202 | повтор отдельным span'ом |
| Все SQL внутри pay | единицы миллисекунд | база ни при чем |
| **pay целиком** | **2 689 мс** | из них ожидание внешних систем ~2.5 с |

Вывод: pay ждет внешние системы внутри запроса. Профиль CPU этого не видит, потому что ожидание не жжет CPU;
`pg_stat_statements` не видит, потому что это не SQL; RED видит только итог.

Медиана почти не изменилась, хвост вырос заметнее ожидаемых "единиц процентов": при 100 % сэмплировании каждый pay
пишет ~34 span'а, а под фоновым штормом еще и каждый hold. Отсюда тезис занятия: в проде 1-10 % head-sampling и
tail-sampling в коллекторе (оставлять все медленные и ошибочные трейсы). Памяти: otel-collector 74 МиБ из 256, Tempo 418 МиБ из 512
(на пределе, при долгих прогонах следить).

## Слом акта 3: письмо в горутине (`break-goroutine.txt`)

`FAULT_NOTIFY_MODE=goroutine FAULT_CRASH_AFTER_COMMIT=order.paid`: pay отвечает 200 за 323 мс (горутина соблазнительно быстра),
билет выпущен (I3 зеленый), через 100 мс процесс падает, письмо умирает вместе с ним: **I5 красный**, первый красный инвариант курса.
Это dual write: запись в БД и отправка письма без общей транзакции. Лечение: outbox в той же транзакции (ветка `demo/l4-cdc`).
