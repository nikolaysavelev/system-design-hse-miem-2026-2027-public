# Акт 2. Кластер и выкатка без простоя

Ветка `demo/l5-k8s`, прогоны 02.10.2026. Кластер k3d (1 server + 2 agent) в сети compose-стенда, чарт `deploy/charts/soldout`. Сводка: `../results.md`.

## Сеть под → compose

`network.txt`: проверка первого варианта, через `host.k3d.internal` и опубликованные порты (PostgreSQL 5432, PgBouncer 6432, Valkey 6379, OTLP 4317, mailgw 8090, Kafka 29092 с listener `EXTERNAL`). Все порты открыты, брокер объявляет себя адресом, доступным из пода.

Этот путь на Docker Desktop идет через прокси хоста. checkout 60 с через ingress:

| | через `host.k3d.internal` | кластер в сети compose |
|---|---|---|
| RPS | 685 | 1 147 |
| pay p99 | 1.04 с | 723 мс |
| покупок в секунду | 124 | 200 |

Поэтому узлы кластера подключены к сети compose, а поды ходят по именам сервисов. `checkout-baseline.txt`: второй столбец.

## Выкатка под нагрузкой

`make checkout` 60 с, выкатка на 15-й секунде. Файлы: `<имя>-k6.txt` (итог k6), `<имя>-rollout.txt` (вывод выкатки), `<имя>-pools.txt` (PgBouncer и число подов).

| Прогон | Что выкатывали | Ошибки | pay p99 |
|---|---|---|---|
| `checkout-baseline` | ничего | 0 из 69 330 | 723 мс |
| `no-readiness` | две версии подряд без readiness и preStop | 2 520 из 65 778 (3.83 %) | 797 мс |
| `readiness` | версия с readiness и preStop, один под | 0 из 121 404 | 615 мс |
| `readiness-2` | то же, два пода (HPA поднял вторую реплику) | 0 из 64 107 | 1.11 с |

В `no-readiness-k6.txt` ошибки распределены по всем шагам сценария: запрос попадал в под, который уже получил SIGTERM и перестал слушать.

В `readiness-2-pools.txt` видно, откуда рост p99: на 25-й секунде 4 пода и 100 клиентов в очереди PgBouncer при 20 серверных соединениях.

## I6 при двух репликах

`i6-before-fix.txt`: до миграции 0022 после четырех прогонов checkout при двух подах 5 132 проданных места остались в проекции карты "held" (I6: 10 264 расхождения). `invariants-after-rollouts.txt`: после исправления те же прогоны, все инварианты зеленые.
